# Проверка ReplayKit 2.0.0

Локально: сборка без предупреждений; 6 Core + 52 Windows-проверки успешны.
Новые проверки декодируют H.264 при 15/60 FPS и AAC с синтетическим сигналом, проверяют сохранение готового MP4 при блокировке файла, сохранность существующего назначения, паузу/продолжение, экспорт выбранного диапазона из RAM, фиксацию снимка, очистку при блокировке, открытие просмотра, закрепление и OCR синтетического текста.
Просмотр интерфейса: история, настройки, редактор, видеобуфер, закреплённый кадр и сравнение. Результаты создаются в игнорируемом `artifacts/qa/`.

Отдельный 30-минутный real-time прогон (`--soak`) проверяет одновременно MP4, секундную историю и 60-секундный RAM-видеобуфер. Источник синтетический; эта проверка не подтверждает аудиоустройства или видеодрайвер. Окончательный результат будет добавлен после завершения прогона.

Непроверенные аппаратные сценарии: разблокированный DXGI/WGC с реальным окном, WASAPI на физических устройствах и долговременная A/V-синхронизация, HDR/вертикальные мониторы, полная матрица Windows 10/11 и DPI 100–250%. На локальной машине Windows заблокирован; тест `--capture` требует видимого тестового окна и не объявляется успешным без этого условия.
WGC использует BGRA8; специальное HDR tone mapping не реализовано. Частоты 15/30/60 — целевые; при перегрузке очередь MP4 отбрасывает старые кадры, сохраняя ограниченный расход RAM. Видеобуфер использует MJPEG в RAM и H.264 только при экспорте. Размер, FPS и лимит памяти документированы в README.

## Автоматические проверки

6 проверок Core: обороты кольцевого буфера, хронологический порядок, неизменность снимка после записи и очистки, исключение кадров старше минуты и кадров из будущего, параллельное чтение/запись, валидация горячих клавиш.

38 Windows-проверок: JPEG в RAM, исходные размеры, PNG без изменения декодированных пикселей, регистрация/конфликт/обмен глобальных сочетаний, 60 готовых превью, фиксация истории, крайние позиции таймлайна, выбор кадра <100 мс, непрозрачное скрытие, отмена/повтор, обрезка в исходных пикселях, собственная рамка и прозрачность всех трёх окон, цвета текста при смене темы и разворачивание без перекрытия панели задач.

Реальный DXGI: Intel UHD Graphics 620, 1920×1080, JPEG получен в RAM. Воспроизведено получение пустой чёрной поверхности при первом обновлении одного курсора (LastPresentTime=0). Такие уведомления теперь не заменяют сохранённый полноценный кадр. Это соответствует [описанию DXGI_FRAME_INFO Microsoft](https://learn.microsoft.com/windows/win32/api/dxgi1_2/ns-dxgi1_2-dxgi_outdupl_frame_info).
На этапе финальной проверки локальный сеанс заблокирован (WTS SessionFlags=0, сверху LockApp); сопоставление пикселей видимого тестового окна через DXGI требует разблокировки. Тест `--capture` проверяет это условие явно, без ложного успешного результата.
Максимальное время выбора готового кадра в локальной проверке — 9,41 мс, включая обновление WPF layout. Это измерение выбора превью; первое декодирование истории и время отображения физическим монитором в него не входят.

Видео проверяется встроенным кодеком и декодером Media Foundation: 60 синтетических кадров, H.264/MP4, 1024×640, временные метки, цвета и ориентация первого/последнего кадра. Проверены сохранность существующего файла при отмене пустой записи и остановка при изменении разрешения.
Отдельные проверки запускают настоящий рабочий поток CaptureService и MP4-кодирование с подставленными синтетическими изображениями: старт/стоп, единственная активная запись, одновременный буфер, секундная периодичность после JPEG-кодирования, независимость паузы буфера, блокировка, смена монитора и штатный выход. Готовые MP4 снова декодируются. Эти проверки не подтверждают работу видеодрайвера и не сохраняют пользовательский рабочий стол.

GitHub Actions дополнительно компилирует Inno Setup и проверяет установку в HKCU, запуск self-contained приложения, штатное завершение через `--quit`, удаление установленных файлов.
Результат конкретного запуска доступен в [Actions](https://github.com/domovoyproj/ReplayKit/actions).

## Визуальная проверка

Изображения интерфейса со синтетическим кадром: `artifacts/qa/history-dark.png`, `history-light.png`, `editor-dark.png`.
Проверены читаемость, скругления, тени, ползунок, лента превью и панели действий. При узком окне действия истории переходят на вторую строку; инструменты редактора переносятся.

Per-Monitor V2 и размещение окна в физических координатах реализованы. Полная ручная матрица Windows 10/11, смешанных DPI 100–250%, вертикальных/HDR-мониторов, сна и блокировки на разных драйверах не выполнена и не заменяется синтетическими тестами.
Исполняемые файлы не подписаны сертификатом издателя.

## Graphify

Установлен `graphifyy 0.9.77`. Использованы `extract . --code-only`, `query`, `affected`, `god-nodes`, `explain`, `cluster-only`, `export html` и `diagnose multigraph`.
`graphify-out/` исключён из Git. AST не извлекает символы из некоторых PowerShell и top-level файлов; связи INFERRED остаются предположениями.
Диагностика графа обнаруживает две самоссылки вызовов, без потерянных концов рёбер или схлопывания разных рёбер. При извлечении повторяющегося namespace ReplayKit.Views инструмент сообщает о совпадающем ID и сохранении одного узла пространства имён; это ограничивает точность графа. Graphify также сообщает о сохранённых узлах двух существующих файлов вне текущего сканирования; эти ограничения инструмента не скрываются.
Граф используется для навигации по связям, а поведение проверяется сборкой и тестами.
